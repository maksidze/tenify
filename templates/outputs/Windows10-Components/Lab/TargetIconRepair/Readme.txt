Targeted desktop-folder / pinned Explorer icon repair

Setup-TargetIcons.ps1
  Changes ONLY File Explorer.lnk IconLocation to the verified private
  explorer.exe.mun, index0. The executable target/PIDL is unchanged.
  Forces extraction of ONLY C:\Users\MAKSIDZE\Desktop\Wub's thumbnail through
  the verified no-VFS resource adapter in an own bounded noninteractive child.
  No desktop.ini is written, no global icon/thumbnail cache is deleted, no shell
  is restarted, and no SHChangeNotify/UI input is sent.

Restore-TargetIcons.ps1 [-Journal <absolute journal.json>]
  Restores exact original shortcut bytes only if current bytes equal our recorded
  AfterSHA256. A changed or deleted shortcut is preserved. Repeated restoration
  is harmless. Before any setup, Restore reports NoActiveRepair.
  Thumbnail cache databases are NOT restored/deleted. The cached item remains
  ordinary derived shell data and can be regenerated by Windows. This restore
  command does not claim to reverse the displayed thumbnail or current shell's
  in-memory image list.

TargetIcons.ps1 -Action Status
  Reports active journal and current shortcut hash without changing them.

One-click integration
  Call Setup-TargetIcons.ps1 after verifying the no-VFS icon component. Reuse is
  idempotent: the original backup is retained; unchanged Wub content fingerprint
  skips repeated extraction. -SkipThumbnail allows pin-only repair.
  A foreign change returns PreservedForeignChange rather than overwriting it.
  Parse the JSON Status if the caller needs to distinguish a full application
  from a preserved external customization. Exceptions cause nonzero failure.
  No production main launcher is modified by this lab.

Ownership and rollback
  - One Local named mutex serializes this tool's setup/restore operations.
  - PinIcon.exe runs on a staging COPY. PIDL bytes are compared after Save.
  - Durable before.lnk, prepared after.lnk and journal precede any real write.
  - The real shortcut is opened once with read+write access and FILE_SHARE_READ
    only. Thus concurrent writes/renames are denied while the verified handle is
    held. Hash, physical path and non-reparse attributes are checked on this
    handle. Write/length/flush/readback all use it, not a later pathname lookup.
  - A caught write failure restores original bytes while retaining that handle.
    An abrupt machine/process failure can leave WritePending: the next invocation
    accepts only exact BeforeSHA/AfterSHA; unknown partial/foreign bytes are not
    overwritten. Keep before.lnk for explicit manual recovery in that case.
  - PinIcon and FolderCacheProbe start suspended on never-switched desktops,
    assigned to our kill-on-close job before resume. CREATE_NO_WINDOW throughout.
    Parent deadlines are20s/55s; FolderCacheProbe also has its own45s watchdog.
  - System files, unrelated processes and the active Explorer are untouched.
